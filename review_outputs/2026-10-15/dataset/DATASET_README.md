# Simulated parking review dataset

## Origin and scope

This is a deterministic synthetic dataset generated by the existing SQLite demo-data generator and prediction feature builder. No real-world measurements are included. The review database contains five configured slots and is isolated from the application database.

- Generator seed: `20260908`
- Sampling interval: 5 minutes
- Time coverage (UTC): 2026-08-01T00:00:00Z through 2026-08-14T23:55:00Z
- Feature buckets: 4,032; raw records: 6,274
- Model features: 27; target: `next_occupancy_ratio`

## Files

- `parking_raw.csv`: privacy-safe context samples, session entry/exit records, and allocation objective components. Direct vehicle, session, RFID, and idempotency identifiers are excluded.
- `parking_features.csv`: chronological features from the existing shared `build_feature_timeline` implementation, plus the next-interval occupancy target. The last row has no future target and is blank.
- `dataset_metadata.json`: machine-readable schema, split, scaler, limitations, and SHA-256 details.
- `parking_dataset.zip`: this README, metadata, and both CSV files.

## Feature definitions

- `occupancy_ratio`: occupied slots divided by configured capacity
- `occupancy_change`: current occupancy ratio minus previous interval ratio
- `occupancy_mean_15m`: mean occupancy ratio over the last three intervals
- `occupancy_mean_60m`: mean occupancy ratio over the last twelve intervals
- `hour_sin/hour_cos`: cyclic local-clock position; timestamps are UTC
- `weekday_sin/weekday_cos`: cyclic day-of-week position
- `weather_*`: one-hot weather category indicators
- `holiday/event`: simulated binary calendar/event indicators
- `entry_count/exit_count`: session starts/ends in the five-minute interval
- `allocation_count`: allocations recorded in the interval
- `active_session_count`: sessions active at interval end
- `unique_vehicle_count`: distinct simulated vehicles represented by sessions in the interval
- `returning_vehicle_rate`: share of interval entries by previously observed vehicles
- `mean_walking_distance/mean_congestion/mean_fairness`: mean normalized allocation component, or zero without allocations
- `allocation_present`: one when at least one allocation exists in the interval
- `next_occupancy_ratio`: occupancy ratio in the next five-minute interval; last row has no future target

## Prediction and preprocessing

The target `next_occupancy_ratio` is occupancy ratio five minutes after each feature timestamp. Each example uses the preceding twelve intervals (60 minutes). The chronological split is 70% train, 15% validation, and 15% test before window construction; actual sequence counts are train 2,810, validation 592, and test 594.

Continuous features are standardized using training-partition values only. Bounded and cyclic encodings follow the shared preprocessing contract. The feature builder carries short gaps forward and leaves longer gaps unresolved; sequence construction excludes windows spanning unresolved buckets. This export has no unresolved buckets. RFID values never enter model arrays.

## Limitations

All observations are simulated. The generator does not model a measured site, actual weather, camera accuracy, physical throughput, or real waiting times. Five-slot results may not generalize to other facilities.

## Reproduction and checksums

From the repository root, run `make review-dataset`. The command recreates the dedicated review database and all exports using the seed and interval listed above. SHA-256 checksums for the raw and feature CSV files are recorded in `dataset_metadata.json`.
